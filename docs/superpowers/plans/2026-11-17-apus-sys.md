# apus-sys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every Swift runtime ABI definition into one C header in a new `apus-sys` crate and generate the Rust side, the symbol lists and the calling-convention checks from it.

**Architecture:** `sys/include/apus/abi.h` is the only place the ABI is written. clang compiles the funclets and thunks against it; bindgen output (committed) gives Rust its declarations; a test reads the header's clang AST to prove that each Swift-CC function Rust calls directly lowers like a C call. macOS 14 is the floor; macOS 15 declarations are optional (`dlsym` accessors) unless the `macos15` feature raises the floor.

**Tech Stack:** Rust 2021, `cc`, `bindgen` (dev-dependency, exact version), `serde_json` (dev-dependency), Xcode clang/libclang, `objdump`.

**Spec:** `docs/superpowers/specs/2026-11-17-apus-sys-design.md` (Korean). Read it before Task 1; section numbers below refer to it.

## Global Constraints

- Apple only: `apus-sys` stops with `compile_error!` unless `target_vendor = "apple"`. libclang and clang come from Xcode (`xcrun`).
- ABI source: swiftlang/swift `swift-6.4.2-RELEASE`; `#define APUS_SWIFT_ABI_TAG "swift-6.4.2-RELEASE"`; every header item cites its original file and name; layouts only, no copied code.
- Floor macOS 14 (`-mmacosx-version-min=14.0`, or the environment's higher `MACOSX_DEPLOYMENT_TARGET`); `macos15` feature raises it to 15.0 and fails the build if `MACOSX_DEPLOYMENT_TARGET` is set below 15.
- `apus` depends on `apus-sys = { path = "sys", version = "=0.1.0", optional = true }`, enabled by the `swift` feature; `macos15` in `apus` enables `apus-sys/macos15`.
- `apus-sys` dependencies: `cc` (build) only. `bindgen` and `serde_json` are dev-dependencies.
- Markers: `APUS_C`, `APUS_DIRECT`, `APUS_THUNK`, `APUS_ASYNC`, `APUS_INTERNAL` (spec 4.2); `APUS_AVAILABLE(15.0)` (spec 4.7). Thunks are named `apus_<declared name>`.
- Swift-CC functions never return `_Bool` in the header; they return `uint8_t`, read as `& 1`.
- `apus`'s public API does not change; `AsyncFunctionPointer` and `RetRegs` stay opaque (`#[repr(transparent)]` wrappers).
- No GPL code (eugenehp/rswift is off-limits). Bindings come from bindgen; no hand-written duplicates of header items in Rust.
- Fewer tests (owner): the only new test files are `sys/tests/lowering.rs` and `sys/tests/fresh.rs`; the existing suite (96 tests) must stay green.
- Commits on `feat/runtime`, one per task, message trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No push.

## Review Focus

1. A build with only the `dispatch` feature must not build `apus-sys` nor need the Swift runtime — Task 1 adds the check.
2. Someone on another Xcode (different libclang) runs `cargo test`: `fresh` prints a skip, it does not fail — Task 3 adds the check.
3. x86_64: the funclets, thunks and generated bindings build and run under Rosetta, not just arm64 — Task 4 adds the check.
4. A downstream binary (example) links `apus` and runs: the rpath to `/usr/lib/swift` still reaches it after the move — Tasks 1 and 4 run an example.
5. `macos15` with `MACOSX_DEPLOYMENT_TARGET=14.0` stops the build with a message naming both values — Task 5 adds the check.

- [ ] **Step 1: Write `sys/tests/lowering.rs`** (`harness = false`, a `main` like today's `tests/abi_equivalence.rs`).   - an `APUS_THUNK` without a declared `apus_{name}`: `"{name}: APUS_THUNK without apus_{name}"`.
  - an `APUS_C` declaration with a Swift attribute: `"{name}: APUS_C but Swift-CC"`.
